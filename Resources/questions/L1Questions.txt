# Inodes, Hard Links & Symbolic Links (Topic 3)

### 53.
A developer deleted a 20GB log file (`/var/log/app.log`), but `df -h` shows disk space was not freed. `du -sh` shows the file is gone.
What is happening, and what exact commands do you run to identify and release the trapped space without rebooting?

### 54.
Why does creating a hard link across different disk partitions/filesystems fail with `Invalid cross-device link`, whereas a symbolic link succeeds?

### 55.
Explain why Linux kernel prevents directory hard links, while directory symbolic links are widely used. What issues would directory hard links cause for backup tools and `find`?

### 56.
How do you identify whether a symbolic link is broken (dangling), and how do you find all hard links associated with a specific inode number?

# User & Group Management, Dotfiles & Security (Topic 4)

### 57.
A user logs in via SSH and their prompt displays `-bash-4.2$` instead of `[username@hostname ~]$`.
1. What is the root cause?
2. What exact commands do you run to restore their environment and prompt?

### 58.
A security scanner flags a non-root account `app_admin` with `UID 0` in `/etc/passwd`.
Why is this a CRITICAL risk, and what effective privileges does `app_admin` possess on the OS?

### 59.
An admin ran `usermod -G devops alex` to add `alex` to group `devops`. `alex` immediately lost access to `docker` and `sudo` (`wheel`).
What mistake did the admin make, and what exact command should have been executed?

### 60.
Explain the difference between `/etc/passwd` and `/etc/shadow`. Why is `/etc/passwd` world-readable while `/etc/shadow` is restricted to mode `0400` / root-only?

### 61.
A CI/CD deployment service account `gitlab-runner` was created with `useradd -r -M -s /sbin/nologin gitlab-runner`.
Why does SSH deployment fail with `Permission denied`, and how do you resolve it while keeping the account secure?

### 62.
Trace the Bash initialization sequence for an SSH login shell. In what exact order are `/etc/profile`, `~/.bash_profile`, `~/.bashrc`, and `/etc/bashrc` executed?

# Interview Rule

During our mock interviews:
- One question at a time.
- Expect follow-up questions.
- Explain your reasoning before commands.
- Justify every troubleshooting step.
- Avoid guessing.
- If you don't know, explain how you would find the answer.
- I will interrupt vague answers just like a real interviewer.
- The interview ends only when I am satisfied with your depth of understanding.
