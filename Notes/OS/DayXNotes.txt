

An Operating System is system software that acts as a bridge between applications/users and the computer hardware.

It manages hardware resources and provides services so that applications can run safely and efficiently.

------------------------------------------------------------

Simple Example

Suppose Chrome wants to open a file.

Chrome does NOT directly talk to the SSD.

Instead

Chrome
 ↓
Operating System
 ↓
SSD

The OS performs the work and returns the result.

------------------------------------------------------------

Responsibilities of an Operating System

1. CPU Management

The OS decides which program gets CPU time.

2. Memory Management

The OS allocates RAM to applications.

3. Storage Management

The OS reads and writes files.

4. Device Management

The OS controls keyboards, mice, printers, USB devices, disks, etc.

5. Security

The OS prevents applications from interfering with one another.

6. Process Management

The OS creates, schedules and terminates processes.

7. Networking

The OS manages network communication.

------------------------------------------------------------

Why do we need an Operating System?

Without an Operating System,

every application would have to

- communicate with hardware
- manage memory
- schedule CPU
- communicate with storage
- communicate with network cards

This would become extremely difficult.

Different applications could even fight for hardware resources.

The OS solves these problems.

------------------------------------------------------------

Example

Suppose

Chrome needs CPU.

Spotify needs CPU.

VS Code needs CPU.

Without an OS

they all try to use the CPU directly.

Chaos.

With an OS

The OS decides

who gets CPU
when
and for how long.

# Chapter 4 - What does Unix-like mean?

Unix was an operating system developed at Bell Labs in the 1970s.

It introduced many ideas:

- Everything is a file
- Multi-user systems
- Multitasking
- Powerful shell
- Small command-line tools
- Permissions
- Hierarchical file system

Linux was built independently but follows many of these ideas.

Therefore,

Linux is called

Unix-like

It behaves similarly but is not the original Unix.

------------------------------------------------------------

# Chapter 5 - Why doesn't Windows become Unix?

Windows has millions of existing users and applications.

Changing Windows into a Unix-like operating system would break compatibility.

Instead,

Microsoft added Linux features to Windows.

Examples

- WSL
- OpenSSH
- PowerShell
- Git
- Linux Containers

This preserves compatibility while supporting modern development workflows.

# Chapter 9 - Virtual Memory

Virtual Memory is a memory management technique.

Every process believes it owns a large continuous block of memory.

Actually,

the Operating System translates

Virtual Address

↓

Physical RAM Address

Advantages

- Process isolation
- Security
- Easier memory management

------------------------------------------------------------

# Chapter 10 - Swap Memory

Swap is disk space used as an extension of RAM.

Suppose

RAM = Full

Instead of crashing,

Linux moves less frequently used memory pages

RAM
↓

Swap (Disk)

This creates free RAM for active programs.

Important

Swap is MUCH slower than RAM.

------------------------------------------------------------

# Chapter 11 - Pages

The Operating System does not manage RAM byte by byte.

Instead,

it divides memory into fixed-size blocks called

Pages

Typical size

4 KB

Memory management becomes easier because the OS moves and tracks pages rather than individual bytes.

# Chapter 13 - CPU Scheduling

CPU Scheduling decides

Which process gets CPU time?

Remember

CPU Scheduling

≠

Memory Management

These are different concepts.

Common Scheduling Algorithms

- FCFS (First Come First Served)
- Round Robin
- Priority Scheduling
- Shortest Job First

------------------------------------------------------------

Round Robin

Every process gets a small time slice.

If unfinished,

the process goes to the back of the queue.

Fairness is the main objective.

------------------------------------------------------------

Priority Scheduling

Higher-priority processes execute before lower-priority ones.

------------------------------------------------------------

FCFS

The first process to arrive runs first.
